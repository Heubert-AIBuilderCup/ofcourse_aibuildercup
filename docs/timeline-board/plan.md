# Your road — Implementation Plan

**Intent:** docs/timeline-board/intent.md (criteria 1–18). **Spec:** docs/timeline-board/board-reference/design-prompt.md ("spec §n"). **Reference build:** docs/timeline-board/board-reference/board-reference/ — road-logic.txt (the logic: BASE scene data, buildScene, camera frame/target/animTo/clampCam, bindMap input, press, renderVals' tile/label/ruler maths), RoadB.dc.html (the markup per size and state), road.css (the look, map field tokens --fld/--ink, hit clip-paths, label placement, phone road), login.css (Industry tokens). Visual reference: the canvas's Board page (boards RoadB*, RB*).
**Goal:** "Your road" at `/road`: the board a finished student lands on, per the intent.
**Approach:** A new feature `src/features/road`. Pure model first (fixture behind a data interface, scene builder, camera maths, URL state, press-to-card), then the routes and the onboarding hand-off, then the map, the card column and its states, then the phone views. The map is the reference's structure: an SVG of isometric tile polygons and roads, with HTML layers over it for labels, the year ruler, the duck and the hint, and invisible real `<button>`s over each tile (44px or more, clipped to the tile's shape). A `road/layout.tsx` renders the board once, so its camera and session state persist across `/road`, `/road/learn/[lesson]` and `/road/route/[routeId]`; those child pages only choose what the card column (or the phone sheet) shows.
**Test layers:** unit (bun test, happy-dom) for every rule: camera fit per stop and size, the scene builder, press-to-card, URL parse/serialize, the replace/push history rules, deep links, Back closing the lesson and the list, the onboarding redirect and landing. No DB layer: nothing is stored (session state only) and the profile read is today's `getProfile`. End-to-end (Playwright, asked for in the intent, criterion 17): zoom via buttons and wheel, swap with Undo, the stack, the lesson open/close, the phone Road/Map switch; written in task 5 and run by the controller against a running dev server. Criterion 18 is the controller's screenshot comparison.
**Constraints:** CLAUDE.md in full; in short: Bun only; server actions return ActionResult and never throw (none planned); Tailwind 4 semantic tokens, container-query variants (`@max-xl:`, `@5xl:`), type/spacing roles, `size-icon*`, no arbitrary breakpoints or `max-w-[…]`; student URLs are named and keyed by stable ids; "test the brain, not the beauty"; read src/design-systems/industry/DESIGN.md before UI and node_modules/next/dist/docs before Next.js code (App Router routing, layouts persisting across child routes, `useSearchParams`, using the history API with the router); never `bun run test:db`, `db:reset` or a dev server; the e2e suite only in task 5's own spec; commit after each task (Conventional Commits, never a co-author line). Every action is the shared `Button` (variants `strong`, `outline`, `text`, `square` + `icon-lg`), notes are `Note`, motion comes from src/shared/components/motion.module.css; behaviour lives in components, never per page. Map login.css's tokens onto the existing ones (the map field: `--panel` (blue light, steel dark), its ink `--panel-foreground`; accents the `accent-*` ramp); add no token.
